# 모바일 디자인 전면 개편 — Phase 1: 메인 화면 + 공용 셸

## 배경 / 왜 지금

디자이너가 Figma(`ToGather_Design`, fileKey `cjB2vAxWxHDuRIQbIPgDdy`)에 모바일 전체 화면(33개)을
새로 그렸다. 사용자가 PNG로 내보낸 파일을 `~/Downloads/모바일 디자인/`에 모아뒀고, 아이콘 에셋은
이미 `togather-front/src/assets/mob-icon/`에 내보내져 있다(42개 SVG, 이번 세션에서 이미 커밋됨).

33개 화면을 한 번에 바꾸는 대신 **메인(홈) 화면부터** 순서대로 진행하기로 사용자와 합의했다.
단, 메인 화면을 Figma대로 맞추려면 모든 모바일 화면이 공유하는 헤더/하단탭/드로어도 같이
바뀌어야 한다는 걸 확인했고, 사용자가 "다 같이 figma대로 바꿔"라고 명시적으로 승인했다.

이 문서는 Phase 1(공용 모바일 셸 + 메인 화면)의 범위를 고정한다. 이후 화면(교회소개, 마이페이지,
성경읽기/필사, 로그인, 주일학교 등)은 별도 Phase로 이어간다.

## 목표

- `src/layouts/RootLayout.jsx`의 `MobileHeader` / `MobileDrawer` / `BottomNav`를 Figma
  `m_Main_menu`(node `1058:7229`) 디자인대로 재구성한다.
- `src/pages/Home/MobileHome.jsx`를 Figma `m_Main`(node `999:10366`) 디자인대로 재구성한다.
- 새로 생기는 섹션(갤러리)과 기존 섹션(공지 알림, 예배 영상, **이번주 말씀**)은 전부 실제 백엔드
  API로 채운다 — 목업 텍스트를 화면에 남기지 않는다. ("이번주 말씀"은 데스크톱
  `MessageSection.jsx`가 이미 쓰는 `sermon.scripture` 기반 실데이터 패턴을 그대로 가져온다.)
- 아이콘은 전부 `mob-icon`(1순위) 또는 기존 `web-icon`(보완) 에셋을 재사용한다. 새 아이콘 파일을
  만들지 않는다.
- 데스크톱 레이아웃·라우팅·데이터 계약은 건드리지 않는다 — `md:` 분기 바깥(데스크톱 쪽)은 변경 없음.
- 지금 모바일 헤더에만 있는 `/교적부` 진입점을 홈 퀵메뉴 4번째 자리(원래 "성경 랭킹" 임시 자리)로
  옮겨 보존한다 — 드로어는 Figma 그대로 두고(항목 추가 없음), 대신 목적지가 불확실했던 퀵메뉴
  슬롯을 실제 존재하는 기능으로 채운다(사용자 확정, 결정 번복: 처음엔 드로어에 넣기로 했었으나
  이 방식으로 변경).

## 비목표 (Non-goals)

- 메인 화면 이외의 32개 모바일 화면(교회소개/마이페이지/성경읽기·필사/로그인/주일학교 등)은
  이번 Phase에서 다루지 않는다. 다음 Phase에서 순서대로 진행한다.
- "성경 랭킹" 기능 자체는 현재 프론트/백엔드 어디에도 없다 — 이번 Phase에서 만들지 않는다.
  Figma가 그 라벨을 붙여둔 홈 퀵메뉴 4번째 자리는 랭킹이 아니라 **교적부**로 채운다(사용자 확정,
  아래 "에셋"/"결정 사항" 참고).
- 알림(bell) 아이콘이 가리키는 "알림 목록" 화면/기능이 없다 — 이번 Phase에서 만들지 않는다.
  아이콘은 눌러도 아무 동작 하지 않는 비활성 상태로 둔다(사용자 확정).
- 디자인 시스템 토큰(색상) 추가 없음 — Figma에 쓰인 색은 전부 `tokens.css`의 기존
  `blue-*`/`bluegrey-*`/`grey-*`와 hex가 정확히 일치함을 확인했다(예: blue-6 `#3D5588`,
  bluegrey-2 `#F6F6F8`). 새 토큰을 추가하지 않고 기존 유틸리티 클래스만 쓴다.

## 안티골 (이게 되면 실패)

- 헤더/하단탭/드로어를 바꾸면서 데스크톱(`md:` 이상) 네비게이션이 깨지면 실패.
- 홈 화면의 실데이터(공지, 예배 영상, 갤러리)가 하드코딩 mock으로 남아있으면 실패 — 이전 세션에서
  이미 "더미 데이터 확인" 작업을 여러 차례 했던 영역이라 같은 실수를 반복하면 안 된다.
- 로그인 안 한 사용자가 드로어를 열었을 때 깨지거나(에러) 로그인 사용자 전용 UI(프로필/로그아웃만)가
  그대로 노출되면 실패.
- `/교적부` 진입점이 홈 퀵메뉴 4번째 자리 어디에도 없어서 모바일에서 교적부 접근이 완전히
  막히면 실패.

## 확인된 사실 (Figma 리딩 결과)

### 공용 셸 — 지금 코드 vs Figma

| 영역 | 지금 (`RootLayout.jsx`) | Figma 신규 디자인 |
|---|---|---|
| 헤더 | 왼쪽 교적부 아이콘 / 가운데 로고 / 오른쪽 햄버거 | 왼쪽 로고+교회명 / 오른쪽 알림종(`bell-01`, 알림 기능 없어 비활성 — 사용자 확정) + 햄버거(`menu-01`) |
| 하단탭 | 성경 / 주보 / **홈(가운데 떠있는 원형, 흰 아이콘)** / 캘린더 / 마이페이지 | 홈 / 예배 / 성경 / 캘린더 / 마이페이지 — 5개 전부 같은 크기, 활성 탭은 알약(pill) 배경으로만 구분 |
| 드로어 | `church.nav`를 평면 나열, 로그인 여부에 따라 로그인/회원가입 ↔ 마이페이지/로그아웃 | 상단 프로필(아바타+이름), 5개 섹션으로 그룹화된 메뉴, 하단 "로그아웃" 버튼 (로그아웃 전용 — 로그인 전 상태는 Figma에 없음, 사용자 확인: 기존처럼 로그인/회원가입 버튼으로 대체) |

드로어 섹션/항목 (Figma `m_Main_menu` 텍스트 그대로 — 항목 추가 없음, 교적부는 드로어가 아니라
홈 퀵메뉴 쪽에 넣는다. 아래 "메인 화면" 참고):
- **교회소개**: 예배시간, 섬기는 사람들, 안내
- **주일학교**: 유치부, 초등부, 중고등부, 대학청년부
- **전도・선교**: 전도회 소개, 국내외 선교, 선교지 소식
- **양육・훈련 게시판**: 구역 모임, 오늘의 묵상, 제자 훈련, 양육 프로그램, 양육・훈련 게시판, 성경 읽기/쓰기
- **교회 소식**: 공지사항, 교회행사, 갤러리

이 그룹/항목 구성은 지금 데스크톱이 쓰는 `church.config.js`의 `nav`(교회소개 7개 자식, 예배·방송
별도 그룹 등)와 **항목 수·그룹이 다르다**. 데스크톱 `nav`를 변형하면 데스크톱이 깨지므로, 모바일
드로어 전용 네비게이션 데이터를 별도로 둔다(아래 "빌더 재량" 참고).

### 메인 화면 — 섹션 구성 (Figma `m_Main` 그대로)

1. 검색바 (기존 `MobileSearchBar`와 동일 — 변경 없음)
2. **이번주 말씀** — 현재처럼 "설교 요약 불릿 목록"이 아니라 **성경 구절 인용 카드 하나**로 바뀜
   (날짜 chip + 인용문 + 출처). 세리프 폰트(Figma `Noto Serif KR`) 사용 — 코드베이스에 이미
   로드된 `Gowun Batang`(주보 표지 등에서 이미 성경 인용에 쓰는 바로 그 서체,
   `JuboV1Page1.jsx`/`JuboV2Page1.jsx` 참고)로 대체해 새 폰트 로드를
   추가하지 않는다.
3. **퀵메뉴 4아이콘** (신규) — 교회소개(`/교회소개`) / 행사・소식(`/교회행사`, 사용자 확정) /
   스마트 주보(`/주보`) / **교적부**(`/교적부`, 사용자 확정 — Figma 라벨은 "성경 랭킹"이지만 그
   기능이 없어서 이 자리를 교적부로 대체. 라벨 텍스트도 "교적부"로 표시).
   아이콘: 앞 3개는 `mob-icon/icon-main-menu-01~03.svg` 그대로 재사용. 4번째는 Figma의 "성경
   랭킹"용 책더미 그래픽이 교적부와 의미가 안 맞아 쓰지 않고, 대신 지금 `MobileHeader`가 이미
   쓰고 있는 교적부 인라인 SVG(책/장부 모양, `RootLayout.jsx`의 기존 path)를 그대로 가져와 쓴다
   (사용자 확정 — 새 아이콘 파일 추가 없음).
4. **예배 영상** — 기존과 동일 구조(LIVE 배지 + 썸네일 + 제목), 레이아웃만 Figma에 맞춰 조정.
5. **공지 알림** — 기존 로직(상단 고정 1건 + 나머지 목록) 유지하되, Figma는 나머지를 **가로
   스크롤 카드가 아니라 세로 리스트**로 보여준다. 데이터 소스(`getNotices`) 변경 없음.
6. **갤러리** (신규) — `getPhotos(church.id, { limit: ... })`로 최근 사진 N장을 가로 스크롤
   카드로 노출, 제목+날짜 표시. `더보기` → `/갤러리`.
7. **푸터** — MobileHome에 새로 만드는 게 아니다. `RootLayout.jsx`가 이미 모든 모바일 페이지
   하단에 `Footer.jsx`의 모바일 분기(114~189행)를 전역으로 렌더링하고 있어서 홈도 이미 푸터를
   갖고 있다. 다만 지금 모바일 푸터는 (a) `isHome` 다크 테마(`bg-primary-darker`)가 적용되고
   (b) SNS 아이콘 행이 있고 (c) Copyright 줄이 없는데, Figma는 홈에서도 밝은 배경
   (`bluegrey-2` `#F6F6F8`)에 SNS 없이 주소/TEL·FAX/Copyright 세 줄만 보여준다. 그래서 이번
   Phase는 `Footer.jsx`의 모바일 분기를 Figma에 맞게 **수정**한다: `isHome` 다크 테마 분기를
   모바일 쪽에서는 쓰지 않고 항상 밝은 배색으로 고정 + Copyright 줄 추가(SNS 아이콘 유지 여부는
   빌더 재량 — 아래 참고). 데스크톱 분기(22~112행)는 손대지 않는다.

### 에셋

- `bell-01`, `menu-01`, `icon-main-menu-01~04`, `search-sm`, `pin-02` → 전부 `mob-icon/`에 이미
  파일명까지 정확히 존재. 그대로 재사용.
- `chevron-right`("더보기" 화살표) → `mob-icon`에는 없고 `web-icon/chevron-right.svg`에 있음 —
  그걸 재사용.
- 하단탭 5개 아이콘(Figma: `hugeicons:home-04`, `hugeicons:note`, `iconoir:book`,
  `solar:calendar-broken`, `solar:user-broken`)은 아이콘 라이브러리 벡터라 `mob-icon`에 정확히
  일치하는 파일이 없다. 지금 코드(`RootLayout.jsx`의 `IconBible`/`IconHome`/`IconCalendar`/
  `IconMyPage` 등)도 이미 인라인 SVG 컴포넌트 방식이므로, 같은 방식 유지하며 path만 Figma 디자인에
  맞게 다시 그린다(이미지 파일로 받지 않음 — 기존 코드 컨벤션 그대로).
- 공지/갤러리의 실제 사진·텍스트는 전부 API 데이터로 대체 — Figma 목업 텍스트("옥길교회 웹사이트
  2026 ver.가 업데이트...", "2024년 유치부 여름성경학교" 등)는 구현에 쓰지 않는다.
- Figma의 교회명("새빛세광교회")과 주소는 샘플 교회 목업이다 — 실제로는 전부 `church.name`,
  `church.address` 등 기존처럼 동적으로 채운다(지금도 `ChurchLogo`/`Footer.jsx`가 이렇게 동작 중).

- 정확한 Tailwind 클래스/spacing 수치는 Figma `get_design_context` 응답(이미 받아둔 `m_Main`,
  `m_Main_menu` 코드)을 기준으로 구현 시점에 다시 조회해 맞춘다.
- 모바일 드로어 전용 nav 데이터 구조(어디에 둘지 — `church.config.js`에 `mobileNav` 필드 추가 vs

- 테스트: 기존에 `MobileHome.test.jsx`가 있으므로, 섹션이 바뀐 만큼 테스트도 같이 갱신한다.
