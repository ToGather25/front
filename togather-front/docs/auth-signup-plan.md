# 회원가입 · 로그인 개선 계획

## 전체 플로우 요약

```
[성도] 가입 신청 (이름·생년월일·휴대폰)
  → [시스템] 신청 완료 안내
    → [관리자] 어드민에서 승인
      → [시스템] 알림톡/이메일 발송 (링크 + 토큰)
        → [성도] 링크 클릭 → 계정 생성 (아이디·비번)
          → 가입 완료 + 자동 로그인 → 메인 홈
```

## 현황 vs 목표 GAP 분석

### STEP 1 — 가입 신청 (`/register`, `Register.jsx`)

| 항목                      | 현재 상태                                                                                   | 목표                                                                                                  | 작업 필요 여부       |
| ------------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | -------------------- |
| 이름·생년월일·휴대폰 입력 | ✅ 구현됨                                                                                   | 동일                                                                                                  | —                    |
| 개인정보 동의 체크박스    | ✅ 구현됨                                                                                   | 동일                                                                                                  | —                    |
| 중복 신청 예외 처리       | ⚠️ 인라인 에러로 표시                                                                       | **모달**로 변경 + 문구 수정                                                                           | 수정 필요            |
| 중복 모달 문구            | "이미 존재하거나 승인 처리 중인 계정입니다."                                                | "이미 등록되었거나 승인 대기 중인 휴대폰 번호입니다. 교회 사무실로 문의해주세요."                     | 수정 필요            |
| 완료 안내 문구            | "관리팀의 승인 후 가입 링크를 보내드립니다. 승인 완료까지 1~2 영업일이 소요될 수 있습니다." | "성도 확인을 위해 관리자 승인 대기 중입니다. 승인이 완료되면 입력하신 번호로 가입 링크가 발송됩니다." | 문구 수정 필요       |
| 중복 확인 API 연동        | ❌ mock (항상 false)                                                                        | 실제 API — 휴대폰 번호로 PENDING/ACTIVE 여부 확인                                                     | **백엔드 연동 필요** |

### STEP 2 — 계정 생성 (`/register/next?token=...`, `SignupNext.jsx`)

| 항목                  | 현재 상태                     | 목표                                                      | 작업 필요 여부                  |
| --------------------- | ----------------------------- | --------------------------------------------------------- | ------------------------------- |
| URL 토큰 파싱         | ✅ 구현됨                     | 동일                                                      | —                               |
| 토큰 유효성 검증      | ❌ TODO 주석만 있음           | 서버에서 토큰 검증 후 유효/만료 처리                      | **백엔드 연동 필요**            |
| 환영 문구 (이름 매칭) | ❌ 없음 (단순 "계정 만들기")  | 토큰으로 이름 조회 후 "OOO 성도님, 환영합니다!" 상단 노출 | 추가 필요                       |
| 아이디 입력           | ✅ 텍스트 형식만              | 이메일 또는 일반 텍스트 모두 허용                         | 확인 필요                       |
| 아이디 중복 확인 버튼 | ⚠️ 버튼 있으나 TODO, 미연동   | 중복 확인 통과 시에만 제출 버튼 활성화                    | **API 연동 + 활성화 로직 필요** |
| 비밀번호 규칙         | 영문+숫자 8자 이상            | 영문+숫자+**특수문자** 조합 8자 이상                      | 정규식 수정 필요                |
| 제출 버튼 활성화 조건 | 현재: submitting 상태만 체크  | 중복 확인 통과 + 비밀번호 일치 시에만 활성화              | 수정 필요                       |
| 가입 완료 후 이동     | 완료 모달 → `/login`으로 이동 | 완료 팝업 후 **자동 로그인 → 메인 홈(`/`)**               | 수정 필요                       |

### STEP 3 — 관리자 승인 (`/admin/members`, `MembersManage.jsx`)

| 항목              | 현재 상태                         | 목표                                              | 작업 필요 여부       |
| ----------------- | --------------------------------- | ------------------------------------------------- | -------------------- |
| 가입 신청 목록 탭 | ❌ 없음 (ACTIVE 회원 목록만 있음) | **"승인 대기"** 탭 추가 (PENDING 상태 목록)       | 추가 필요            |
| 승인 버튼         | ❌ 없음                           | 각 신청 row에 [승인] 버튼 → 상태를 ACTIVE로 변경  | 추가 필요            |
| 알림 발송 트리거  | ❌ 없음                           | 승인 시 시스템이 알림톡/이메일 발송 (백엔드 처리) | **백엔드 연동 필요** |

### STEP 4 — 알림 발송 (시스템)

> 프론트엔드 작업 없음. 백엔드에서 처리.
> 발송 문구 (참고용):
> "**[알곡교회]** 성도 인증이 완료되었습니다. 아래 링크를 통해 로그인 계정 설정을 완료해 주세요. 🔗 [링크]"

## 프론트엔드 작업 목록 (우선순위 순)

### P1 — 코드만 수정 가능 (백엔드 없이)

- [ ] `Register.jsx` — 중복 에러를 인라인 → **모달**로 변경, 문구 수정
- [ ] `Register.jsx` — 완료 안내 문구 수정
- [ ] `SignupNext.jsx` — 비밀번호 정규식에 특수문자 추가
- [ ] `SignupNext.jsx` — 제출 버튼 활성화 조건 추가 (중복 확인 통과 + 비번 일치)
- [ ] `SignupNext.jsx` — 완료 후 `/login` 대신 자동 로그인 후 `/`로 이동
- [ ] `MembersManage.jsx` — "승인 대기" 탭 UI 추가 (더미 데이터로 먼저 구성)
- [ ] `MembersManage.jsx` — 각 대기 row에 [승인] 버튼 추가 (클릭 → mock 처리)

### P2 — 백엔드 연동 시 작업

- [ ] `Register.jsx` — 휴대폰 중복 확인 API 연동 (`POST /api/register/request`)
- [ ] `SignupNext.jsx` — 토큰 유효성 검증 API 연동 (`GET /api/register/verify?token=...`)
- [ ] `SignupNext.jsx` — 토큰으로 이름 조회 후 환영 문구 표시
- [ ] `SignupNext.jsx` — 아이디 중복 확인 API 연동 (`GET /api/register/check-username`)
- [ ] `SignupNext.jsx` — 계정 생성 API 연동 (`POST /api/register/complete`)
- [ ] `SignupNext.jsx` — 완료 후 자동 로그인 API 연동
- [ ] `MembersManage.jsx` — PENDING 목록 API 연동
- [ ] `MembersManage.jsx` — 승인 버튼 API 연동 (`PATCH /api/admin/members/:id/approve`)

## 참고 — 회원 상태값 (백엔드 협의용)

| 상태       | 설명                                              |
| ---------- | ------------------------------------------------- |
| `PENDING`  | 가입 신청 완료, 관리자 승인 대기 중               |
| `APPROVED` | 관리자 승인 완료, 알림톡 발송됨, 아직 계정 미생성 |
| `ACTIVE`   | 계정 생성 완료, 정상 로그인 가능                  |
